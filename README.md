# Todo App

モダンなデスクトップアプリケーション開発F/Wについて、メモリ使用量やCPU使用率を比較するための簡単なTodoアプリ

## 内容

### 機能要件

#### 1. Todoアイテム管理

##### 1.1 作成機能
- **UI**: モーダルダイアログまたは別ウィンドウで入力フォームを表示
- **入力項目**:
  - タイトル（必須、最大200文字、先頭・末尾の空白は自動トリム）
  - 説明（任意、最大500文字、改行可、先頭・末尾の空白は自動トリム）
- **バリデーション**:
  - タイトルが空の場合は保存不可（エラーメッセージ表示）
  - タイトルが200文字を超える場合は保存不可（エラーメッセージ表示）
  - 説明が500文字を超える場合は保存不可（エラーメッセージ表示）
- **自動記録**: 作成日時をISO 8601形式で自動記録（UTC時刻）
- **操作**: 「保存」ボタンで追加、「キャンセル」ボタンで閉じる
- **ID生成**: 
  - 各アイテムに一意のID（UUID v4形式）を自動付与（内部識別用）
  - 表示用の通し番号（1から始まる連番）を自動付与（作成順に割り当て、削除時も番号は維持）

##### 1.2 読み取り機能
- **一覧表示**: すべてのTodoアイテムをテーブル形式（表形式）で表示
- **テーブル構造**:
  - **列構成**（左から順）:
    1. **選択列**: 選択用チェックボックス（各行に配置）
    2. **ID列**: 通し番号（表示用、右寄せ、固定幅）
    3. **タイトル列**: タイトル（最大表示幅に応じて省略表示可）
    4. **説明列**: 説明（任意、折り返し表示、長い場合は省略可）
    5. **ステータス列**: 完了状態コンボボックス（ドロップダウン、完了/未完了の切り替え用）
      - セル内にコンボボックスを表示
      - 選択可能な値: 「未完了」「完了済み」
      - 現在の状態を表示（未完了/完了済み）
      - クリックでドロップダウンを開き、状態を変更
      - 変更は即座に反映（ダイアログ不要）
    6. **作成日時列**: 作成日時（ローカル時刻で表示、フォーマット: YYYY-MM-DD HH:mm、固定幅）
- **テーブルヘッダー**:
  - 各列にヘッダーを表示
  - **選択列ヘッダー**: 全選択・解除用チェックボックス
    - すべてのアイテムが選択されている場合はチェック状態
    - 一部のみ選択されている場合は中間状態（indeterminate）
    - クリックで全選択/全解除を切り替え
  - **ステータス列ヘッダー**: フィルタドロップダウンメニュー（Excel風）
    - ヘッダーにフィルタアイコンまたはドロップダウンボタンを表示
    - クリックでドロップダウンメニューを表示
    - メニュー項目: 「すべて」「アクティブ（未完了）」「完了済み」
    - 選択中のフィルタを視覚的に表示（チェックマーク等）
- **ソート**: 作成日時の降順（新しいものから）でデフォルト表示
- **仮想化**: 100件以上のアイテムがある場合は、仮想化テーブルまたはページネーションを実装（フレームワークの推奨方法に従う）
- **空状態**: Todoアイテムが0件の場合は、適切な空状態メッセージを表示
- **行選択**: 
  - 選択列のチェックボックスで個別に選択/解除
  - ヘッダーの全選択チェックボックスで一括選択/解除
  - 選択された行は視覚的にハイライト表示（任意）

##### 1.3 更新機能
- **編集方法**: 一覧からアイテムを選択して編集ダイアログを開く、または一覧上でインライン編集
- **編集可能項目**:
  - タイトル（必須、最大200文字、バリデーション適用）
  - 説明（任意、最大500文字、バリデーション適用）
  - 完了/未完了状態（コンボボックスで切り替え、一覧上でも切り替え可能）
- **更新日時**: 編集時に更新日時をISO 8601形式で自動記録（UTC時刻）
- **操作**: 「保存」ボタンで更新、「キャンセル」ボタンで変更を破棄
- **完了状態の切り替え**: 
  - 一覧上のステータス列のコンボボックスで即座に切り替え可能（ダイアログ不要）
  - コンボボックスから「未完了」または「完了済み」を選択
  - 変更は即座に保存される（自動保存）

##### 1.4 削除機能
- **個別削除**:
  - 各アイテムに削除ボタンまたはコンテキストメニューを配置
  - 削除前に確認ダイアログを表示（「削除しますか？」）
  - 削除後は一覧から即座に非表示
- **選択アイテムの一括削除**:
  - 選択列で選択されたアイテムを一括削除
  - 「選択したアイテムを削除」ボタンを配置（選択がある場合のみ有効化）
  - 削除前に確認ダイアログを表示（「選択したアイテム（N件）を削除しますか？」）
  - 選択がない場合はボタンを無効化
- **完了済みアイテムの一括削除**:
  - 「完了済みを削除」ボタンを配置
  - 削除前に確認ダイアログを表示（「完了済みのアイテムをすべて削除しますか？」）
  - 完了済みアイテムが0件の場合はボタンを無効化
- **削除の取り消し**: 実装は任意（フレームワークの制約に応じて）

#### 2. フィルタリング機能
- **フィルタ種別**:
  - **すべて**: すべてのTodoアイテムを表示（完了・未完了問わず）
  - **アクティブ**: 未完了（`isCompleted: false`）のTodoアイテムのみ表示
  - **完了**: 完了済み（`isCompleted: true`）のTodoアイテムのみ表示
- **UI実装**: 
  - ステータス列のヘッダーにフィルタドロップダウンメニューを配置（Excel風の実装）
  - ヘッダーにフィルタアイコン（漏斗アイコン等）またはドロップダウンボタンを表示
  - クリックでドロップダウンメニューを表示
  - メニュー項目:
    - 「すべて」（すべてのアイテムを表示）
    - 「アクティブ（未完了）」（未完了アイテムのみ表示）
    - 「完了済み」（完了済みアイテムのみ表示）
  - 選択中のフィルタを視覚的に表示（チェックマーク、背景色変更等）
  - フィルタが適用されている場合はヘッダーに視覚的インジケーターを表示（任意）
- **状態保持**: フィルタ状態はアプリケーション終了まで保持（永続化は任意）
- **件数表示**: 各フィルタで表示されているアイテム数を表示（例: フッターに "表示中: 5件 / 全10件"）

#### 3. データ永続化
- **保存タイミング**: 
  - アイテムの作成・更新・削除時に自動保存（即座に永続化）
  - アプリケーション終了時にも保存を確実に実行
- **保存形式**: 
  - JSON形式（`data/todos.json`）またはフレームワーク標準の方法（SQLite、IndexedDB等）
  - データ構造はテストデータ形式（後述）に準拠
- **保存場所**: 
  - アプリケーションデータディレクトリまたはユーザーデータディレクトリ
  - フレームワークの推奨方法に従う
- **エラーハンドリング**: 
  - 保存失敗時はエラーメッセージを表示
  - 読み込み失敗時は空のリストから開始
- **データインポート**: 
  - 起動時に`data/todos_*.json`ファイルを読み込んで初期データとして使用可能（実装は任意）

#### 4. UI要件

##### 4.1 レイアウト
- **基本構造**:
  - ヘッダー: アプリタイトル
  - メインエリア: Todoアイテム一覧テーブル（スクロール可能、Excel風のテーブル形式）
    - 固定ヘッダー（スクロール時もヘッダーは常に表示）
    - 列の幅調整（任意、ドラッグで列幅変更）
    - 列のソート（任意、ヘッダークリックでソート）
  - フッター: アクションボタン（新規追加、選択アイテム削除、完了済み削除）とアイテム件数表示
- **テーブル形式の要件**:
  - Excel風のテーブル表示（グリッド形式）
  - 列ヘッダーは固定表示（スクロール時も見える）
  - 行の区切り線を表示（任意）
  - ホバー時に行をハイライト（任意）
- **レスポンシブ**: 
  - ウィンドウサイズ変更に対応（最小サイズ: 600x400ピクセル、テーブル表示のため）
  - テーブル列はウィンドウ幅に応じて自動調整
  - 横スクロールが必要な場合は横スクロールバーを表示
- **スクロール**: 
  - 100件以上のアイテムがある場合はスムーズなスクロールを実装
  - 仮想化テーブルを使用する場合は、スクロールパフォーマンスを最適化

##### 4.2 コンポーネント
- **ボタン**: 
  - 明確な視覚的フィードバック（ホバー、クリック状態）
  - 無効状態の視覚的表示
- **入力フィールド**: 
  - プレースホルダーテキストの表示
  - エラー状態の視覚的表示（赤い枠線、エラーメッセージ）
  - 文字数カウンター（任意、タイトル/説明の最大文字数表示）
- **チェックボックス**: 
  - 明確な視覚的状態（チェック済み/未チェック）
  - クリック領域を十分に確保
- **コンボボックス（ドロップダウン）**: 
  - ステータス列のセル内に配置
  - 現在の選択値を明確に表示（「未完了」または「完了済み」）
  - クリックでドロップダウンを開く
  - 選択可能な値: 「未完了」「完了済み」
  - 選択時に即座に反映（自動保存）
  - 明確な視覚的フィードバック（ホバー、選択状態）
- **ダイアログ**: 
  - モーダル表示（背景を暗くする）
  - ESCキーで閉じる
  - フォーカス管理（最初の入力フィールドに自動フォーカス）

##### 4.3 スタイリング

###### 4.3.1 デザイン原則
- **デザイン哲学**: 
  - モダンでミニマルなデザイン（Material Design、Fluent Design、Human Interface Guidelines等のモダンデザインシステムを参考）
  - 機能性を優先し、装飾を最小限に
  - 一貫性のあるデザイン言語の適用
- **視覚的階層**: 
  - 重要な情報を視覚的に強調（サイズ、色、太さ）
  - 明確な情報構造（ヘッダー、コンテンツ、フッターの区別）
  - 適切なコントラスト比（WCAG 2.1 AA準拠、最低4.5:1）

###### 4.3.2 カラーパレット
- **基本カラー**: 
  - **プライマリカラー**: アクションや重要な要素に使用（例: ボタン、リンク、選択状態）
  - **セカンダリカラー**: 補助的な要素に使用
  - **背景色**: メイン背景、セカンダリ背景、テーブル行の交互背景色（zebra striping）
  - **テキスト色**: プライマリテキスト、セカンダリテキスト、無効テキスト
- **セマンティックカラー**: 
  - **エラー**: エラーメッセージ、バリデーションエラー（赤系）
  - **成功**: 成功メッセージ、完了状態（緑系）
  - **警告**: 警告メッセージ（黄/オレンジ系）
  - **情報**: 情報メッセージ（青系）
- **カラースキーム**: 
  - ライトモードをデフォルトとする
  - ダークモード対応は任意（実装する場合は、すべてのカラーを適切に調整）
- **コントラスト**: 
  - テキストと背景のコントラスト比は最低4.5:1（通常テキスト）、3:1（大きなテキスト）
  - インタラクティブ要素（ボタン、リンク）は明確に識別可能

###### 4.3.3 タイポグラフィ
- **フォントファミリー**: 
  - システムフォントまたはフレームワークの推奨フォントを使用
  - 読みやすさを優先（sans-serif系を推奨）
- **フォントサイズ**: 
  - 本文: 14px以上（推奨: 14-16px）
  - 見出し: 18px以上（推奨: 18-24px）
  - 小さいテキスト: 12px以上（ラベル、補助情報）
  - 最小サイズ: 12px（アクセシビリティのため）
- **フォントウェイト**: 
  - 通常: 400（Regular）
  - 強調: 500-600（Medium/SemiBold）
  - 太字: 700（Bold、見出しや重要な情報）
- **行間**: 
  - 本文: 1.4-1.6（読みやすさのため）
  - 見出し: 1.2-1.4
  - リスト: 1.3-1.5

###### 4.3.4 スペーシング
- **統一されたスペーシングシステム**: 
  - 4pxまたは8pxのベース単位を使用（例: 4px, 8px, 12px, 16px, 24px, 32px）
  - 一貫性のある余白とパディング
- **コンポーネント間の余白**: 
  - セクション間: 24-32px
  - コンポーネント間: 16-24px
  - 関連要素間: 8-12px
- **コンポーネント内のパディング**: 
  - ボタン: 8-12px（上下）、16-24px（左右）
  - 入力フィールド: 8-12px（上下左右）
  - テーブルセル: 8-12px（上下左右）
  - ダイアログ: 24px（コンテンツエリア）

###### 4.3.5 ボーダーとシャドウ
- **ボーダー**: 
  - 幅: 1px（標準）、2px（強調）
  - 色: 背景色より10-20%暗い色（セパレーター、区切り線）
  - 角丸: 4-8px（ボタン、入力フィールド、カード）、0px（テーブルセル）
- **シャドウ**: 
  - ダイアログ、ドロップダウン: 軽い影（elevation効果）
  - ボタン（ホバー時）: 軽い影（任意）
  - 過度な影は避ける（フラットデザインを基本とする）

###### 4.3.6 アイコン
- **アイコン使用方針**: 
  - 明確で理解しやすいアイコンを使用
  - 一貫性のあるアイコンセット（Material Icons、Font Awesome等）
  - サイズ: 16px, 20px, 24px（用途に応じて）
- **アイコンの配置**: 
  - ボタン内: テキストの前または後
  - テーブルヘッダー: フィルタアイコン、ソートアイコン
  - アクション: 削除、編集、追加アイコン

###### 4.3.7 インタラクティブ要素の状態
- **ボタン**: 
  - **通常**: プライマリカラー背景、白またはコントラストの高いテキスト
  - **ホバー**: 背景色を10-15%暗く、カーソルをポインターに変更
  - **フォーカス**: 明確なアウトライン（2-3px、フォーカスカラー）
  - **アクティブ（プレス）**: 背景色をさらに暗く
  - **無効**: グレーアウト、クリック不可、カーソルをnot-allowedに
- **入力フィールド**: 
  - **通常**: 白またはライトグレー背景、ボーダー
  - **ホバー**: ボーダー色を強調
  - **フォーカス**: ボーダーをプライマリカラーに、アウトライン表示
  - **エラー**: 赤いボーダー、エラーメッセージ表示
  - **無効**: グレーアウト背景、クリック不可
- **チェックボックス**: 
  - **未チェック**: 白背景、ボーダー
  - **チェック済み**: プライマリカラー背景、チェックマーク
  - **ホバー**: 背景色を薄く表示
  - **フォーカス**: アウトライン表示
  - **無効**: グレーアウト
- **コンボボックス**: 
  - **通常**: 入力フィールドと同様
  - **オープン**: ドロップダウン表示、選択中の項目をハイライト
  - **ホバー（項目）**: 背景色を薄く表示
  - **選択済み**: 明確に表示（背景色、チェックマーク等）

###### 4.3.8 テーブルのスタイリング
- **テーブル全体**: 
  - 背景: 白またはライトグレー
  - ボーダー: 1px（外枠、列間の区切り線）
  - 角丸: なし（フラットデザイン）
- **テーブルヘッダー**: 
  - 背景: セカンダリ背景色（通常より10-15%暗い）
  - テキスト: セミボールド（500-600）
  - パディング: 12px（上下）、16px（左右）
  - ボーダー: 下部に1pxの区切り線
  - 固定表示（スクロール時も見える）
- **テーブル行**: 
  - **通常行**: 白背景
  - **交互行（zebra striping）**: ライトグレー背景（任意、可読性向上）
  - **ホバー**: 背景色を薄く表示（10-15%暗い）
  - **選択行**: プライマリカラーを薄く表示（20-30%透明度）
  - **パディング**: 8-12px（上下左右）
- **テーブルセル**: 
  - ボーダー: 右側に1pxの区切り線（任意）
  - テキスト配置: 左寄せ（ID列は右寄せ）
  - 垂直配置: 中央揃え
- **セル内コンポーネント**: 
  - チェックボックス、コンボボックスはセル内に適切に配置
  - セル内のパディングを考慮

###### 4.3.9 ダイアログのスタイリング
- **背景**: 
  - モーダル背景: 半透明の黒（50-70%透明度）
  - ダイアログ本体: 白背景
- **レイアウト**: 
  - 角丸: 8-12px
  - パディング: 24px
  - シャドウ: 軽い影（elevation効果）
  - 最大幅: 600px（レスポンシブ）
- **ヘッダー**: 
  - タイトル: 18-20px、セミボールド
  - 閉じるボタン: 右上に配置
- **フッター**: 
  - ボタン配置: 右寄せ
  - ボタン間隔: 8-12px

###### 4.3.10 一貫性と統一性
- **デザインシステム**: 
  - すべてのコンポーネントで一貫したスタイルを適用
  - 再利用可能なスタイルコンポーネントの使用
- **命名規則**: 
  - セマンティックなクラス名またはスタイル名を使用
  - フレームワークの推奨命名規則に従う
- **レスポンシブ**: 
  - 異なるウィンドウサイズで適切に表示
  - 最小幅: 600px、最小高さ: 400px
  - テーブルは横スクロール可能（必要に応じて）

##### 4.4 アクセシビリティ
- **キーボード操作**: 
  - Tabキーでフォーカス移動
  - Enterキーで保存/確定
  - ESCキーでキャンセル/閉じる
- **スクリーンリーダー**: 
  - 適切なラベルとARIA属性の設定（フレームワークがサポートする場合）
- **フォーカス表示**: 
  - キーボードフォーカスの視覚的表示（アウトライン等）

##### 4.5 エラーハンドリングとフィードバック
- **エラーメッセージ**: 
  - ユーザーフレンドリーなエラーメッセージを表示
  - バリデーションエラーは該当フィールドの近くに表示
- **成功フィードバック**: 
  - 保存成功時は視覚的フィードバック（任意、トースト通知等）
- **ローディング状態**: 
  - 大量データの読み込み時はローディングインジケーターを表示（任意）

  - `todos_100.json`: 100件のサンプルデータ
  - `todos_1000.json`: 1000件のサンプルデータ

**データ形式**:
テストデータはJSON形式で、以下の構造を持ちます：

```json
[
  {
    "id": "uuid-string",
    "title": "タスクタイトル（最大200文字）",
    "description": "タスクの説明（最大500文字、任意）",
    "createdAt": "ISO 8601形式の日時文字列",
    "isCompleted": false
  }
]
```

**注意事項**:
- `id`フィールドはUUID v4形式の文字列（内部識別用）
- 表示用の通し番号（1から始まる連番）は、データには含めず、表示時に作成日時の順序に基づいて生成する
- 通し番号は削除後も維持される（削除されたアイテムの番号は欠番となる）
- 各フレームワークの実装では、このデータ形式を読み込んで使用してください

### WinForms除外理由

WinFormsは比較対象から除外しています。理由は以下の通りです：

- **デザインの自由度不足**: WinFormsでは、一般的なモダンUIを作成することができない。フレームワーク自体が持つ制約により、テーブルヘッダーへのフィルタアイコンの配置や、モダンなUIパターンの実装が困難または不可能である

上記の理由により、WinFormsは実用的な比較対象として不適切と判断し、除外しています。
